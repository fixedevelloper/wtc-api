# État de l'adaptation des frontends à l'API Spring

Complète le [guide de migration](frontend-migration.md) (généré) : ce qui a été fait dans chaque client, les choix, ce qui reste.

## Back-office web (`wetransfertjs`, Next.js)

- **Couche réseau unique** `src/lib/api/http.ts` : base `/api`, jeton Bearer, erreurs `problem+json` (`ApiError.code`), `Idempotency-Key` sur les opérations d'argent. Variable `NEXT_PUBLIC_API_URL` ; l'origine du site doit figurer dans `CORS_ALLOWED_ORIGINS` côté API (le navigateur appelle l'API directement).
- **Authentification** (NextAuth + API) : connexion, **double authentification obligatoire pour le personnel** (code à 6 chiffres, écran d'activation avec QR code `/auth/mfa-setup`), **renouvellement du jeton d'accès par le refresh token à rotation** (côté serveur NextAuth, les jetons ne sont jamais dans la session exposée au navigateur), déconnexion si le renouvellement est refusé. Écrans de réinitialisation de mot de passe (`/auth/recover-password`, `/auth/reset-password?token=`) : les e-mails de l'API pointent vers `{WTC_WEB_BASE_URL}/auth/reset-password`.
- **Écrans réécrits** : transferts (liste filtrée côté serveur, détail avec historique et créations d'ordre chez le fournisseur (confirmations et suivis : dans l'historique uniquement), remboursement, relecture du statut Wace, **saisie pour un client avec devis du serveur** et `expectedTotalDebit`), clients (KYC avec examen des documents, portefeuilles, **demande d'ajustement à double validation**), page des ajustements (approbation par un autre administrateur), recharges (examen des preuves), expéditeurs/bénéficiaires (composants partagés), barème de frais (tranches clôturées, jamais modifiées) et zones, pays (banques, villes, opérateurs par code ISO, import Wace), jetons web WhatsApp (jeton affiché une fois), personnel (invitation, rôles, suspension, réinitialisation 2FA), journal d'audit et connexions.
- **Choix** : le back-office ne crée plus d'expéditeur ni de bénéficiaire (l'API n'offre pas de création côté administration) : la saisie d'un transfert utilise ceux que le client a enregistrés. Les profils clients ne sont plus modifiables par le personnel (seul le statut du compte l'est).
- **Reste** : réconciliation Wace (non implémentée côté API), tableau de bord alimenté par l'API (les statistiques sont des exemples). Vérifié par `tsc` et `next build` ; pas de test automatisé du front, pas d'essai dans un navigateur.

## Application Android (`transfertWeDoc`)

- **Couche réseau** : DTOs et `ApiService` du contrat (`/api/...`), traduction vers les modèles d'écran dans `Mappers.kt` (les écrans gardent leurs champs). **Renouvellement automatique du jeton** sur 401 (`TokenAuthenticator`, verrou, refresh à rotation, jamais sur `/api/auth/`), jetons chiffrés par le Keystore. Un 403 n'est plus une déconnexion. Erreurs `problem+json` : message en français selon le code (`INSUFFICIENT_FUNDS`, `QUOTE_CHANGED`…).
- **Identifiants** : tous les identifiants de clients, parties et transferts deviennent des UUID (chaînes) ; les pays sont désignés par leur code ISO.
- **Parcours d'envoi refait en 4 étapes** (destinataire → compte → montant avec **devis du serveur** → confirmation) : un compte bancaire ou mobile est une **destination** du bénéficiaire (comptes enregistrés, numéros masqués, ou nouveau compte) ; les frais, le taux et le total viennent du serveur et sont renvoyés (`expectedTotalDebit`) ; **`Idempotency-Key`** stable pour un même contenu (pas de double débit si l'utilisateur ou le réseau rejoue). Motifs, relations et origines des fonds s'envoient par code, selon le type de transfert (P2P, P2B…).
- **Reçu PDF officiel du serveur** (partagé via FileProvider). **Double authentification** (code) si le client l'a activée ; avertissement si la pièce d'identité a expiré ; **version minimale** exigée au démarrage (`/api/meta/client-requirements`) ; mot de passe oublié réel.
- **Recharges** : mobile money (opérateur + téléphone du payeur, validation sur le téléphone, plus de page web) et preuve de paiement. **Les routes `/api/me/top-ups` ne sont pas encore implémentées côté API (phase 7 : documentation Pay-In de Wace attendue)** : l'écran renverra une erreur tant que la phase 7 n'est pas faite.
- **PayLink / factures / retraits** : microservice distinct, **non adapté** : il identifie les clients par l'ancien identifiant numérique. L'écran de création de lien est protégé contre l'identifiant UUID (message « indisponible ») ; le service doit être adapté pour accepter les jetons et identifiants de l'API Spring.
- **Vérifié par** : compilation, APK de débogage, 22 tests unitaires JVM (traductions, erreurs, clés d'idempotence, renouvellement du jeton). Pas d'essai sur appareil ni contre l'API réelle.
